# Официальный и промежуточный ответ

Скрипт: [`docs/Ответы+на+оспаривания.sql`](../docs/Ответы+на+оспаривания.sql).  
В конце скрипта два шаблона: `Otvet_na_osparivanie` и `Promezhutochnyy_otvet_na_osparivanie`. Нужный XML выбирается регионом организации.

## Когда какой ответ

| Ситуация | Что слать | Тег |
|----------|-----------|-----|
| Сверили, править нечего | Финальный | ОфОтв |
| Выгрузка/3.1/удаление НБКИ/Экви/demerge ещё не подтверждены | Промежуточный | ОфОтв_Пр |
| ОКБ: только удаление запроса, файл-просьба ушёл | Это и есть финал | ОфОтв, задачу можно закрыть |
| ССП: просьба ушла в бюро-отправитель оспаривания | Финал сразу | ОфОтв |

**Стоп:** финал клиенту/в письмо оспаривания не формировать, пока НБКИ/Экви не подтвердили удаление запросов или бюро не приняло корректировку (кроме сценариев «сразу закрываем» выше).

## Как заполнить скрипт

Переменные шапки — [09-sql.md](09-sql.md) §10. В шапке меняются только они:

```sql
DECLARE @xml AS XML
       ,@org AS SMALLINT = 6
       -- 1 МФК Саммит, 4 ЦВ, 5 ПКО Доброзайм, 6 МКК ДЗБР
       ,@creditBureau AS NVARCHAR(50) = N'АО «НБКИ»'
       -- АО «НБКИ» | АО «БКИ «Скоринг Бюро» | АО «ОКБ»
       ,@dateOfMail AS NVARCHAR(50) = '13.01.2026'           -- сегодня
       ,@numberMailFromBureau AS NVARCHAR(50) = 'ИСХ///236314'
       ,@dateMailFromBureau AS NVARCHAR(50) = '22.12.2025'
       ,@FIO AS NVARCHAR(300) = N'Козык Евгений Евгеньевич'
       ,@answer AS NVARCHAR(MAX) = N'…текст по существу…'
```

Два ИСХ в одном пакете (Саммит + ПКО) — два прогона, два файла, два `@org`.

Выполнить, забрать XML (`SELECT @xml`), оформить файл по правилам бюро, подписать, зашифровать, отправить.

Шапка письма (реквизиты) — скрипт **КДЗ**, вложение к инструкции ОЧ.

## Что писать в `@answer`

Закрыть **все** пункты входящего письма.

| Просили | Формула |
|---------|---------|
| Проверить договор / просрочку, в ПО и бюро ок | «информация по договору с УИД: {uid} отображается корректно» + явно просрочка / закрытие / продажа (покупатель и дата) |
| Банкрот, код 16 на месте | «… отображается корректно, статус договора „Банкрот“» |
| Титул: в ПО уже как просит заявление | «ФИО / паспорт серии … № … выдан ДД.ММ.ГГГГ отображаются корректно» — не «исправили», если ничего не меняли |
| Заявка «не оформлял», анкета подписана | «заявка с УИД: … оформлена, анкета подписана» (статус 4/11 не меняет формулу) |
| Заявка стала договором | «заявка с УИД: … перешла в договор, информация отображается корректно» |
| Удалить запросы ОКБ | Файл `DIV_01465` (Саммит) / `DIV_02680` (ПКО) / `DIV_02650` (ДЗБР); в `@answer` просьба удалить запрос (шаблон Word) |
| Удалить запросы НБКИ | В финале после ACK: «запросы от ДД.ММ.ГГГГ удалены файлом {имя}»; до ACK — промежуточный или ждать |
| Удалить запросы Экви | Сначала `0OA_del_zapros_…`, после ACK — `0OA_otvet_na_zapros_{фамилия}_{ДДММГГГГ}` |
| ССП | «просим удалить запрос от {дата} (ССП) в {бюро, где запрос}» |
| После выгрузки | Что отправили, что принялось, что в ЛК теперь верно |
| Заявка отсутствует в бюро | «информация по заявке с УИД: … не отображается в бюро» — только если это правда |

Не писать голое «информация корректна», если в письме был список (запросы + заявка + отчество).

Подтверждение — когда ПО уже верное. «Исправили и выгрузили» — только если карточку/договор меняли.

## Имена исходящих файлов (кроме ЗЗ-специфики)

Общее: **«Ответ на оспаривание [Фамилия клиента]»** для ССП и типовых писем.  
ЗЗ: имена DIV / 0OA / NBKI — в [04-zz.md](04-zz.md) и [08-spravochnik.md](08-spravochnik.md).

## Комментарий в задаче и закрытие

В чат задачи одним блоком (после классификации):

- бюро, организация, `keyPart` / `keyDZ` / УИД;
- факты ПО (актуальное ФИО, паспорт, статус, `UuidBegin`, подпись анкеты, GP/продажа);
- вывод по **каждому** пункту письма: подтвердить или править;
- черновик `@answer` и `@org` (два адресата — два текста);
- ключи выгрузок / имена файлов удаления запросов;
- «направил ответ» или «промежуточный, ждём бюро».

Закрывать задачу, когда финальный ответ ушёл **и** других открытых пунктов нет. Промежуточный — задачу не закрывать. Пока НБКИ/Экви не подтвердили удаление запросов — финал не слать (смешанный пакет ждёт тот же ACK).
