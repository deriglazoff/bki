# ОЧ — основная часть

Пример из инструкции: [задача 412972](https://resultforyou.ru/workgroups/group/437/tasks/task/view/412972/).

## Что сделать сотруднику

1. Прочитать Исх/Вх: какие УИД и что именно (просрочка, закрытие, «не я оформлял», продажа).
2. Найти клиента и договор в ПО ([01-poisk-i-sverka.md](01-poisk-i-sverka.md)).
3. Если клиент пишет «договор не мой» — **файлы клиента**: паспорт и **подписанная анкета** к договору.
   - Анкета подписана → договор оформлен нами; частая причина — забыл о займе.
   - Нет анкеты / отказ по мошенничеству — смотреть контур ЗЗ/мошенничество, не штамп «корректно».
4. Сверить договор в ЛК бюро организации-адресата (лучше начать с ОКБ «Сверить сделку»).
5. По предмету спора открыть нужный блок (просрочка → **27**, закрытие → **38 и 56**, продажа → **51**).
6. Сверить график и платежи ПО с блоком 27.
7. Решение:
   - совпадает → ответ по **каждому** пункту письма (не общая фраза);
   - дырка/ошибка в бюро, в ПО верно → выгрузка;
   - ошибка в ПО → правка, затем выгрузка.
8. Дождаться приёма, перепроверить ЛК, затем официальный ответ.

## Частые ветки

### Просрочка

- Считать дни из графика/платежей, сравнить с 27.
- Закрытый договор: признак просрочки и продолжительность в 27 = 0.
- Активный договор: дни считать, не подставлять нули «на глаз».

### Закрытие / прекращение

У закрытого или прекращённого **всегда** блоки **38 и 56**.

- 56 в ОКБ: поиск по ПДн клиента, вниз страницы, «Признак прекращения обязательств» = 1.
- НБКИ/Экви — тоже по ПДн, скрины в Word.

Нет закрытия в одном бюро при закрытии в ПО → массовая или 3.2, потом проверка ЛК.

### «Не оформлял» / мошенничество

Не решать только по статусу в бюро. Нужны анкета и файлы. Без подписи — не закрывать как «корректно».

### Продажа в ПКО

Выгрузку слать **от организации оспаривания и от покупателя**, если договор продан.

### Просрочка после кредитных каникул (КК)

Пример: [задача 416116](https://resultforyou.ru/workgroups/group/217/tasks/task/view/416116/).

1. Договор → **Доп. соглашения** → дата применения КК.
2. Выгрузка **3.5 исключение клиента** (`keyPart`), дождаться «Отправлено».
3. **Массовая** с датой по **дату начала КК** (не позже). Зафиксировать ID в задаче.
4. Старые заявки после исключения можно не переотправлять; новые заявки и договоры — переотправить массовой.
5. Проверить приём. В бюро после даты КК в 27 не должно быть просрочки.
6. На форме договора вкладка **«Особое»**: галка **«не передавать в БКИ»**.
7. Ответ, когда ЛК совпадает с этим.

## Выгрузка по ОЧ (напоминание)

Форма **Отчёты → Выгрузки КИ**:

- организация = адресат письма (+ ПКО, если продажа);
- бюро или «БКИ» (три сразу, общий ключ расчёта);
- тип: массовая / 3.2 / исключение / аннулирование — см. [00-obshiy-algoritm.md](00-obshiy-algoritm.md).

Сформировать вручную или:

```sql
EXEC KI_BKI_PrepareData
    @keyCHL = 53270,  -- ключ расчёта с формы
    @Result = 0,
    @ErrorComm = N'',
    @ErrorCode = 0,
    @needSelect = 1,
    @debug = 0,
    @Message = N''
```

В задаче: ID выгрузок + почему так. Просмотр квитанции: `records_incorrect = 0`. Затем ЛК.

## Текст ответа (ОЧ)

Скрипт — [07-otvet-i-zakrytie.md](07-otvet-i-zakrytie.md). Шапка — скрипт КДЗ (вложение к Word).

В `@answer` писать по факту, с УИД, например:

- «информация по договору с УИД: … отображается корректно» **и** что именно по просрочке/закрытию/заявке, если это просили;
- после выгрузки — что выгрузка принята и в бюро теперь верно.

Задачу закрывать после отправки финального ответа, если других пунктов нет.
