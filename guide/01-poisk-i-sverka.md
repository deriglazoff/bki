# Поиск клиента и сверка с бюро

Общий блок для ОЧ, Б, ЗЗ, ТЧ, ЗС. Логины ЛК — Passwork.

## Найти клиента в ПО

Сначала SQL: [09-sql.md](09-sql.md). Форма — проверка того же факта глазами.

Поиск по одному из:

- `keyPart`
- `keyDZ`
- номер договора
- паспорт (серия слитно: `8012`, не `80 12`)
- ФИО — после нахождения сверить остальные ПДн: однофамильцы бывают

Актуальное ФИО — `Partner.keyFIO` → `Partner_FIO`, не любая строка истории.  
УИД из письма = `Dogovor_Anket.UuidBegin` без `-1` / `-4`.

Дальше: карточка → **История** → нужный договор/заявка по **УИД из письма**.

УИД на форме: клик по строке (на скрине в Word выделен зелёным).  
В договор: буква **«Д»** справа от строки.

Внутри договора для ОЧ/просрочки: **график** и **платежи** (форму платежей растянуть). Что на экране означает каждая зона — скрин в исходной инструкции ОЧ.

## Личные кабинеты бюро

Учётные записи организаций — Passwork. Заходить **под организацией, от которой пришло оспаривание**.

Удобнее всего смотреть договор/заявку/клиента в **ОКБ**.

### ОКБ

1. ЛК → боковое меню **«Работа с кредитными историями»**.
2. **«Сверить сделку»** — договоры (вводим УИД).
3. **«Передача событий»** — заявки и личные данные клиента.
4. В сделке две вкладки:
  - **«Сведения об участнике»** — ПДн;
  - **«Сведения о сделке»** — договор (нужна она).
5. Заявки: вкладка **«Обращения»**, код причины отказа. Поиск также по паспорту.



### НБКИ

ЛК: `https://lk.nbki.ru/Cabinet/login/auth`.  
Порядок кликов — скрины в Word (инструкция ОЧ).

- Договор: найти нужный **блок** и **первую запись по убыванию**.
- Закрытие / нет просрочки: блок **27** — «Признак наличия просроченной задолженности» и «Продолжительность просрочки» = 0 (если договор закрыт).
- Заявка: поле **«УИД заявки»** (не общий УИД формы 422-1).
- Результаты ручных GUTDF: вкладка **«Результаты обработки GUTDF-файлов»**.



### Эквифакс (Скоринг Бюро)

Порядок — скрины в Word. Нужный блок ищется по столбцу **«Тип»**.

## Блоки основной части (GUTDF), которые смотрят чаще всего

Вся информация блоков **18–39** относится к одной сделке. Номер сделки — **УИД в блоке 17**.


| Блок   | Смысл                           | На что смотреть                                           |
| ------ | ------------------------------- | --------------------------------------------------------- |
| 17     | УИД сделки                      | Якорь всех остальных                                      |
| 18     | Общие сведения                  | Тип, дата заключения, срок                                |
| 19     | Сумма и валюта                  | Сумма выдачи                                              |
| 21     | График                          | Должен совпадать с ПО                                     |
| 22     | ПСК                             | Только потребзаймы, не бизнес                             |
| 23     | Изменения договора              | Пролонгация, ставка                                       |
| 24     | Выдача / поручительство         | Факт выдачи денег                                         |
| 25     | Вся задолженность               | Всё, что должен (FIFO)                                    |
| 26     | Срочная задолженность           | Ещё не наступил срок                                      |
| **27** | **Просрочка**                   | Признак 1/0; дни текущей или последней погашенной         |
| 28     | Платежи                         | Факт оплат                                                |
| 29     | Среднемесячный платёж           | Формула бюро                                              |
| **38** | **Прекращение**                 | Почему закрыт; банкрот = код **16**                       |
| 51     | Новый кредитор                  | Продажа в ПКО                                             |
| 54     | Учёт обязательства              | С нашей стороны признак учёта = **1**, иначе — исправлять |
| **56** | Прекращение (витрина ОКБ и др.) | У закрытого/прекращённого всегда должны быть **38 и 56**  |


Шпаргалка по долгу: 25 — всё; 26 — ещё рано; 27 — уже просрочил; 28 — уже заплатил.

Коды блока 38 и коды отказа по заявке — таблицы-картинки в Word, в текст не попали; сверять по скрину инструкции.

## Как считать просрочку из ПО

1. Открыть график + платежи (SQL: `Dogovor_GP`, `MemberPay2` — [09-sql.md](09-sql.md) §6).
2. Дата первого пропущенного платежа (`DatPlatFact` позже `DatPlat`) → от неё растут дни.
3. Полная оплата просрочки → текущей просрочки нет, значение уходит в **продолжительность последней погашенной**.
4. Сравнить с блоком 27 в каждом бюро.

Заявление «исполнено в срок» само по себе не решение: если график показывает просрочку — в ответе подтверждать ПО.

Если в ПО просрочки нет, а в бюро текущая всё ещё идёт — корректировка 3.2 / массовая, не «корректно».
