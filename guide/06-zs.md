# ЗС — склейка и задвоение

Playbook: [../complex-cases/zs-playbook.md](../complex-cases/zs-playbook.md). Агент: скилл `solve-osparivanie` (без автозакрытия).

Источник процесса 3.1 и поиска выгрузки: титульная инструкция.  
Письмо на разделение и связанные задачи — практика ЗС.

## Когда это склейка

В выгрузке в одном из блоков FL1–FL10 ушли **чужие** данные (третье лицо), и бюро склеило СКИ. Чаще FL4–FL6, реже FL1–FL3, ещё реже FL7–FL10.

Не путать с опечаткой в своём паспорте (это ТЧ без чужого субъекта).

## Что сделать сотруднику

1. По письму бюро понять: кто **наш** клиент, кто **третье лицо**.
2. Карточка нашего клиента в ПО: какие поля чужие.
3. Убедиться, что **мы** отправили мусор. Если бюро не назвало выгрузку — письмо в бюро: в каком файле слияние.
4. Если имя выгрузки есть — найти XML на `\\s-bki\КИ\…` (ниже).
5. Перед правкой открыть **ЛК** и увидеть склейку своими глазами.
6. Событие **3.1** по проблемному блоку — тот же процесс, что в [05-tch.md](05-tch.md).
7. После приёма снова ЛК. Критерий успеха — ошибочные данные **пропали** у нашего клиента, не «файл принят».
8. Если после 3.1 по **чужому паспорту** наш клиент всё ещё находится — XLSX на разделение (вложение «файлы на корректировку» к Word): данные третьего лица **и** нашего. Порядок СКИ в файле не важен.
9. Пока бюро не подтвердило разделение — промежуточный ответ, не финал.

Имена файлов разделения:

- НБКИ: `{КОДУЧАСТНИКА}_{ДДММГГГГ}_{ФАМИЛИЯ}_{ИМЯ}_{ОТЧЕСТВО}`  
  пример: `7A01LL000002_07082025_ЛЯМКИНА_ПОЛИНА_СЕРГЕЕВНА`
- ОКБ: `DIV_0{кодучастника}_{ГГГГММДД}_{Фамилии}`  
  пример: `DIV_02650_20250807_LyamkinaIgnatova`
- Экви: сами пришлют файл с рекомендациями, если им нужно.

Почта разделения НБКИ в практике: `demerge@nbki.ru` (плюс файл). Связанные задачи на тот же паспорт — не дублировать выгрузку.

## Где лежат выгрузки

Поиск по проводнику Windows, шара `s-bki`, папка **КИ**, затем бюро. Старые файлы лучше искать **по дате папки**.

| Бюро | Путь |
|------|------|
| НБКИ | `\\s-bki\КИ\НБКИ\ExportService` |
| ОКБ | `\\s-bki\КИ\ОКБ\Unloads` |
| Экви | `\\s-bki\КИ\Эквифакс\NewEquiFax` |

Часто ошибка в **системной** выгрузке: чужое ФИО в XML — не повод откладывать задачу.

Структура XML: `<Subject_FL>` → `<Title>` (титул, по нему искать ФИО) → `</Title>` → `<Events>`. У клиента может быть несколько `Subject_FL`. Поиск по `orderNum`: найти событие, прокрутить вверх до `Title`.

## Чего не делать

- Не вести склейку через автомат удаления запросов (ЗЗ).
- Не закрывать «как в прошлый раз» без сверки обоих субъектов.
- Не считать успехом одну принятую выгрузку без проверки ЛК и поиска по ошибочному паспорту.
