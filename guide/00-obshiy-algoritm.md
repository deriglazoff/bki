# Общий алгоритм задачи

Один проход. Ветки по типу — в отдельных файлах; сюда не прыгать в середину.

```text
Вложения Исх + Вх
    │
    ├─ 1. Разобрать письмо: бюро, организация, что просят, УИД
    ├─ 2. Поставить / проверить тип: ЗЗ | ОЧ | ТЧ | Б | ЗС (смешанный = все теги)
    ├─ 3. Найти клиента и объект в ПО          → 01-poisk-i-sverka.md
    ├─ 4. Сверить ПО ↔ ЛК бюро (как минимум того, от кого письмо)
    │
    ├─ 5. Решение
    │      ├─ данные верные во всех нужных бюро ──► шаг 7 (финальный ответ)
    │      ├─ в ПО верно, в бюро дырка/старое ───► выгрузка / письмо
    │      ├─ в ПО неверно ──────────────────────► правка ПО → выгрузка
    │      └─ нет объекта / противоречие / юр. ──► эскалация, не отказ
    │
    ├─ 6. Если была выгрузка / удаление / 3.1 / demerge
    │      ждать «отправлено» + records_incorrect = 0 + проверка ЛК
    │      пока ждём — промежуточный ответ (ТЧ/ЗС почти всегда)
    │
    ├─ 7. Скрипт «Ответы на оспаривания» → файл → бюро
    └─ 8. Комментарий, теги ОфОтв / ОфОтв_Пр, закрыть если всё закрыто
```

## Шаг 1. Разобрать вложения

В задаче обычно два файла бюро:

| Файл | Зачем |
|------|--------|
| **Исх** | Кто адресат (наша организация), блок «К Вам относится», УИД договоров/заявок |
| **Вх** (заявление) | Что субъект оспаривает: просрочка, паспорт, банкротство, запросы и т.д. |

Дополнительно: сканы паспорта в хвосте заявления, файлы ССП, `claim` / `correction_file`.

Зафиксировать себе:

- бюро-отправитель (НБКИ / ОКБ / Эквифакс);
- организация-адресат (Саммит / ЦВ / ПКО Доброзайм / МКК ДЗБР);
- список УИД и дат;
- полный перечень требований (не только «договор»).

Канцелярию НБКИ (GUTDF, 10 дней, ст. 15.26.3, «удалите запросы» как типовой абзац письма) не считать предметом, если во Вх нет заполненного пункта про запросы.

## Шаг 2. Тип задачи

| Признак | Тип |
|---------|-----|
| Запросы, заявки, ССП, файл на удаление | **ЗЗ** |
| Договор: просрочка, статус, закрытие, сумма, ПКО | **ОЧ** |
| Паспорт, ФИО, адрес, телефон, почта, ИНН, СНИЛС | **ТЧ** |
| Клиент банкрот, код 16, реализация | **Б** |
| Два субъекта, склейка, разделить СКИ | **ЗС** |

Несколько контуров → смешанный пакет: делать **все** контуры, в финале один ответ по всем пунктам.

Подробнее: `classification.md`.

## Шаг 3–4. ПО и бюро

Общий поиск и ЛК: [01-poisk-i-sverka.md](01-poisk-i-sverka.md).

Минимум: организация из письма и бюро из письма. Для ОЧ/Б/ТЧ перед финалом сверять **три** бюро, если данные по договору/титулу уходят во все.

## Шаг 5. Развилка «что делать»

| Наблюдение | Действие сотрудника |
|------------|---------------------|
| ПО = бюро = заявление (или заявление ошибочно, факты в ПО и бюро сходятся) | Финальный ответ «отображается корректно» + по каждому пункту письма |
| ПО верно, в бюро нет договора / нет закрытия / нет продажи / старый титул | Выгрузка (массовая или 3.2 / 3.1) |
| ПО неверно | Сначала исправить карточку/договор, потом корректировочная выгрузка |
| Нет фото нового паспорта / бюро не дало верный СНИЛС | Не выдумывать; удалить поле или уточнить у ОВиА / бюро |
| Договор в портфеле банкротов, статус «выдан» | Юлия Игнатенко, затем корректировки — [03-bankrotstvo.md](03-bankrotstvo.md) |
| Клиент/договор не найден | Эскалация, не отказ |

Тип выгрузки (форма «Выгрузки КИ»):

| Тип | Когда |
|-----|--------|
| **Массовая** | В бюро вообще нет данных; вставляем `keyDZ` |
| **3.2 Корректировка договора** | Не закрыт, не те дни просрочки и т.п. Код изменения: 1 — наша ошибка, 2 — клиента, 3 — мошенничество |
| **3.3 / 3.4 Исключение** | Неточность нашли мы сами (договор / заявка) |
| **4.2 / 4.3 / 4.4 Аннулирование** | Неточность нашли не мы; 4.2 одна запись, 4.3 все договоры клиента, 4.4 все обращения |
| **3.5 Исключение клиента** | Удалить всю информацию по клиенту (в т.ч. займы). Нужен ID клиента |
| **3.1** | Корректировка титула (через пару выгрузок, см. ТЧ). Пункт «3.1 ФЛ56» на форме — устарел |

Организация выгрузки = организация из оспаривания. Если договор **продан** — выгрузка ещё и от организации-покупателя (ПКО).

«БКИ» на форме = сразу три бюро с общим ключом расчёта: договоры, добавленные в одну строку, подтянутся в остальные.

## Шаг 6. После выгрузки

1. Сформировать: кнопка «сформировать выгрузку» **или** `EXEC KI_BKI_PrepareData @keyCHL = …`.
2. Записать в задачу **ID / ключ расчёта** и зачем отправили.
3. Статус зелёный «Отправлено» — ок. Жёлтый — ошибки валидации, исправить, переотправить.
4. Просмотр ответа: выгрузка → «Просмотр» → в message box «Нет». `records_incorrect = 0`.
5. Открыть ЛК бюро и убедиться, что факт изменился (не полагаться только на «файл принят»).
6. Только тогда — финальный ответ.

Пока ждём бюро по ТЧ/ЗС — промежуточный ответ, тег **ОфОтв_Пр**. Финал не слать.

Краткая формула комментария в задаче:
