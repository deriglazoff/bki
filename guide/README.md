# План работы сотрудника по оспариванию КИ

Это рабочий план: **что сделать с задачей**, от вложений до закрытия.  
Источник — инструкции в [`docs/`](../docs/). Скрины интерфейса смотрите в исходных Word.

| Файл в `docs/` | Что из него взято |
|----------------|-------------------|
| `Основная_Часть+,+Банкроты,+Запросы_Заявки (1).docx` | ОЧ, банкротство, запросы/заявки, ССП, просрочка после КК |
| `Титульная_Часть,+Задвоения_Склейки.docx` | Титул FL1–FL10, событие 3.1, склейка |
| `Ответы+на+оспаривания.sql` | XML официального / промежуточного ответа |

## Как пользоваться этой папкой

1. Откройте [00-obshiy-algoritm.md](00-obshiy-algoritm.md) — общий план на **каждую** задачу.
2. Клиента и объекты в ПО — SQL из [09-sql.md](09-sql.md), затем ЛК [01-poisk-i-sverka.md](01-poisk-i-sverka.md).
3. По типу задачи перейдите в нужный файл (смешанный пакет — все затронутые файлы).
4. Ответ и закрытие — всегда [07-otvet-i-zakrytie.md](07-otvet-i-zakrytie.md).
5. Коды, почты, имена файлов — [08-spravochnik.md](08-spravochnik.md).

## Жёсткие правила (не нарушать)

- Клиента или договор **не нашли в ПО** — не отказывать в оспаривании, разбирать вручную / эскалировать.
- **Не отвечать клиенту/бюро финально**, пока выгрузка, удаление запросов (НБКИ/Экви) или разделение СКИ не приняты.
- В ответе закрыть **все** пункты письма (запросы + заявка + отчество — три пункта, не «всё корректно»).
- Сначала сверка ПО: актуальное ФИО/паспорт уже как в заявлении → **подтвердить**, 3.1 не открывать. Заявку «не оформлял» при подписанной анкете — **не исключать**.
- ID выгрузок и логику решения **писать в комментарий задачи**.
- Логины бюро — в Passwork, в план не копировать.
