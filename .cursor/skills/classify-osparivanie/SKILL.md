# Классификация задачи оспаривания

По URL задачи: скачать вложения, классифицировать по `classification.md` в корне репозитория, положить результат **комментарием в задачу**. Правила типов и подтипов не копировать сюда — каждый прогон читать файл. Класс обработки (`правка_БД` и т.п.) не ставить: это входящий предмет спора, не то, что уже сделали.

Интервью не проводить. Задачу не закрывать.

MCP: namespace `user-bitrix24-test`. Если tools недоступны — сначала `mcp_auth`.

## 1. Взять задачу и файлы

ID из URL `.../tasks/task/view/{id}/`.

- `b24_tasks_get` — `chatId`.
- `b24_call("tasks.task.get", { taskId, select: ["*", "UF_TASK_WEBDAV_FILES"] })` — массив `ufTaskWebdavFiles`. Это **attached object id**, не `disk.file` id.
- На каждый id: `b24_call("disk.attachedObject.get", { id })` → `NAME`, `DOWNLOAD_URL`.

Пакет НБКИ: взять **txt** (`ishod.txt` / `vhod.txt`, имена с «исх»/«вх»), если есть; PDF — только если txt нет. Скачивать **локально** по `DOWNLOAD_URL` вложения (`Invoke-WebRequest` / curl). `b24_disk_file_content` с MCP-хоста обычно 403 (WAF `/download/`).

Прочитать оба файла целиком. Шапка Вх (ФИО, паспорт, адрес, телефон) — идентификация, пока тот же факт не повторён в блоке «не согласен». Пустые подпункты без организаций — пропуск.

**Done when:** есть тексты Исх и Вх (или явное «файлов нет» — тогда стоп, комментарий не писать).

## 2. Классифицировать

Прочитать `classification.md` целиком и применить §3, включая «Пакет НБКИ: Исх + весь Вх».

Краткий каркас (детали только в файле):

- Слой A (Исх): адресат + «К Вам относится» → контур **ОЧ** и якоря-УИД. Канцелярия НБКИ (GUTDF, титул в штампе, удаление запросов, ст. 15.26.3, 10 дней) — не предмет спора. Подтипы ОЧ из одного Исх не ставить.
- Слой B (весь Вх): заполненные пункты → ТЧ / ЗС / Б; пункты про УИД адресата → подтипы ОЧ. Чужие УИД не дают ОЧ этому источнику; банкротство и титул из тех же абзацев — дают.
- Несколько контуров → явно «смешанный» и все теги, без сведения к одному доминирующему.

**Done when:** список тегов + подтипы каждого тега с якорем в тексте файлов.

## 3. Комментарий в задачу

BBCode, факты из файлов, не общие слова.

Один тип:

```
[B]Классификация[/B] (по classification.md)

[B]Тип:[/B] {тег} — {расшифровка}

[B]Подтипы:[/B]
• {подтип} — {якорь из файла}
```

Смешанный:

```
[B]Классификация[/B] (по classification.md)

[B]Смешанный пакет[/B]
[B]Теги:[/B] {теги}

[B]{тег}[/B] — {источник}:
• {подтип} — {якорь из файла}
```

В чате уже есть сообщение, которое начинается с «Классификация» → править его: `b24_call("im.message.update", { ID, MESSAGE })` (поле именно `MESSAGE`). Иначе создать: `b24_call("task.commentitem.add", { TASKID, FIELDS: { POST_MESSAGE } })`. `task.commentitem.getlist` / `.update` не использовать (позиционные аргументы, update часто `ACTION_NOT_ALLOWED`).

Проверка: `im.dialog.messages.get` с `DIALOG_ID` = `"chat{chatId}"` — в последнем комментарии теги и подтипы совпадают с шагом 2.

Если запись отклонена — отдать BBCode пользователю и сказать вставить в комментарий задачи.

**Done when:** комментарий виден в чате задачи (или текст отдан пользователю).
