# Статус «ждём бюро» / промежуточный ответ

## Зачем

У ТЧ и ЗС цикл длиннее (медиана ТЧ ~17 дней), часто две итерации с бюро. В корпусе это видно по фразам «направил промежуточный», «ждём ответа от НБКИ», тегу **ОфОтв_Пр** (36 задач, из них 29 ТЧ) — процесс есть, но дырявый: держится на теге и чате.

Нужна **явная сущность статуса**, не только комментарий.

## Модель состояния

```text
new → facts_ready → awaiting_bureau → ready_for_official → closed
         ↑                │
         └──── correction_sent ◄┘
```

| Статус | Смысл | Кто ставит |
|--------|-------|------------|
| `facts_ready` | Карточка собрана, ждём решения сотрудника | Система |
| `correction_sent` | Ушла выгрузка / demerge / письмо в бюро | Сотрудник или интеграция |
| `awaiting_bureau` | Промежуточный ответ клиенту/бюро уже ушёл или можно уйти; финал запрещён | Сотрудник / правило G3 |
| `ready_for_official` | Бюро подтвердило (или сверка «уже корректно») | Сотрудник или мониторинг почты |
| `closed` | Официальный ответ направлен | Как сейчас ОфОтв |

## Правила перехода

1. ТЧ с расхождением, которое чинится выгрузкой → после отправки выгрузки: `correction_sent` → `awaiting_bureau`, `needs_interim = true`.
2. ЗС после письма на разделение → `awaiting_bureau`.
3. Пока статус `awaiting_bureau` / `correction_sent`: UI и рекомендация показывают стоп **«не формировать финальный ответ клиенту»**.
4. Промежуточный ответ — отдельный артефакт (черновик), не путать с ОфОтв.
5. Маппинг на текущие теги Bitrix (переходный период):

| Новый статус | Тег сейчас |
|--------------|------------|
| `awaiting_bureau` + промежуточный ушёл | ОфОтв_Пр |
| Финальный ответ ушёл | ОфОтв |
| Черновик финала | ПрОтв |

## Минимальная реализация на буткемпе

- Поле в задаче / описании: `bureau_wait: yes|no`.
- В рекомендации текст: «Текущий шаг: ждём бюро. Промежуточный: да/нет.»
- Заглушка «ответ бюро получен» вручную для демо.

Полноценный мониторинг почты — общий с 80%-треком; для ТЧ/Б критичнее, чем для ЗЗ.
