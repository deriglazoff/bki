# Playbook ЗС (склейка / задвоение субъектов)

Редкий тип (~2% потока, 41 задача). Не ML: чеклист для сотрудника и для assistive-карточки.  
Операционный гайд: [../guide/06-zs.md](../guide/06-zs.md). Агент: `solve-osparivanie`.

## Когда это ЗС

- Два разных клиента (два `keyPart` / два ФИО) на один паспорт или наоборот.
- В письме: «склейка», «задвоение», «разделить СКИ», запрос на demerge.
- В комментариях истории: `demerge@nbki.ru`, «файл на разделение», чистка `Partner_OldPasp`.

## Чеклист

1. **Идентифицировать субъектов**  
   Два набора: keyPart, ФИО, паспорт(а), какие договоры/заявки у каждого.

2. **Найти связанные задачи**  
   Часто паспорт уже правили в другой задаче ТЧ/ЗС. Не дублировать выгрузки.

3. **Что уже сделано**  
   - Удалён/исключён старый паспорт?  
   - Уже уходило письмо на разделение?  
   - В каком бюро данные ещё склеены?

4. **Действия по бюро**  
   - НБКИ: файл/письмо на разделение (`demerge@nbki.ru` в корпусе).  
   - ОКБ / Экви: отдельная проверка — иногда предыдущие паспорта не передавались, корректировка не нужна.

5. **Промежуточный ответ**  
   Пока бюро не подтвердило разделение — статус «ждём бюро», не финальный ответ клиенту. См. [interim-status.md](interim-status.md).

6. **После подтверждения**  
   Сверить КИ в каждом бюро → «готовь ответ» / официальный ответ.

## Чего не делать

- Не вести ЗС через автомат удаления запросов (ЗЗ).
- Не генерировать SQL восстановления паспорта в чат задачи как «рекомендацию системы».
- Не закрывать задачу по аналогии с одним эталоном без сверки обоих субъектов.
